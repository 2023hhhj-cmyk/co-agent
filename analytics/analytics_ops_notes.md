# Co-Agent 埋点运维说明

> 更新：2026-10-06。配套 [事件与统计规范](analytics_spec.md)。以下是运维配置建议，不表示服务器已应用。

## 单进程与多进程

当前服务入口为单进程。写入器使用 threading.Lock；多 worker 或多实例共写一个日志文件时，没有跨进程锁与完整性保障。共享任务窗口和 LLM 配额也仅在单进程、同事件循环内共享。

扩展前应接入 Redis Stream、数据库或系统日志等外部管道，并由单写者持久化，或各实例分文件后汇总。目前这些方案未实现；不能只增加 Uvicorn worker 数就宣称拥有全局限流和可靠埋点。

## 日志路径与轮转

默认日志为项目内 `analytics/logs/analytics_events.log`，可由 ANALYTICS_LOG_PATH 覆盖。当前写入器每条事件重新打开文件，没有内置轮转。

若服务器沿用 `/root/muzhu-ai/` 且未覆盖日志路径，可配置 `/etc/logrotate.d/co-agent-analytics`：

```text
/root/muzhu-ai/analytics/logs/analytics_events.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
```

按实际账号设置文件访问权限，并验证轮转后进程可创建/追加日志。归档需要容量监控与访问控制；保留时间应按实际数据用途确定。改版后归档旧日志、记录版本和统计区间，避免直接删除历史证据。测试使用独立 ANALYTICS_LOG_PATH。

## 指标使用

日志覆盖天数不能单独保证统计可信。报告应说明样本数量、来源、成功与失败覆盖、版本和时间区间，并区分测试事件与真实业务事件。

当前报告的并行比值、tokens/task 和输入拒绝比例都有统计边界，见 [规范](analytics_spec.md#报告的实际统计口径)。不直接把它们改写成真实加速比、货币成本或攻击检测准确率。工具与反应模式的埋点尚未全覆盖。

## 隐私与故障排查

原始消息、个人信息、凭证、完整参数/输出及错误堆栈不得进入事件字段。调用方负责脱敏，写入器不自动校验或过滤。

| 现象 | 排查 |
|------|------|
| 文件不增长 | 核对 ANALYTICS_LOG_PATH、目录权限、磁盘容量和 DEBUG 日志；写入异常会被吞掉 |
| JSON 行损坏 | 检查多进程共写及外部轮转；报告会跳过损坏 JSON 行 |
| 磁盘增长 | 检查轮转规则、实际路径和归档保留策略 |
| 数字异常 | 检查样本污染、重复事件、未结束任务、字段缺失与统计口径 |
| trace_id 无法关联 | 检查入口 ContextVar 是否设置并传递；临时生成的 ID 不保证贯穿工作流 |

同步写盘有阻塞风险；失败隔离表示写入错误不向业务抛出，不代表没有延迟。ANALYTICS_VERBOSE=1 可镜像事件到 stderr，启用前确认字段已脱敏。
